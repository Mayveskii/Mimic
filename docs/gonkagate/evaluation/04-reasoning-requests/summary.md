# Анализ инцидента: бот ТП не реагирует на сообщения

---

## 1. Три наиболее вероятные причины

### Причина 1: Рассинхронизация данных между Redis и файловым хранилищем
**Обоснование:** Сообщение `[RECONCILER] Цикл завершён` указывает на то, что реконсилятор не смог выполнить синхронизацию. Это может означать:
- Обнаружены конфликты данных (сессия в Redis отличается от файловой копии)
- Реконсилятор исчерпал количество попыток или время ожидания
- Логика разрешения конфликтов дала сбой

### Причина 2: Проблема записи в файловый fallback
**Обоснование:** `[STORE] File sync error` указывает на сбой при записи/чтении файлов:
- Заполнение диска (частая причина в контейнерах)
- Недостаток прав на запись в volume
- Повреждение файловой системы или файлов сессий
- Конкурентный доступ к файлам (race condition)

### Причина 3: Таймаут или блокировка операций Redis
**Обоснование:** Redis отвечает на PING, но это не гарантирует работоспособность всех операций:
- Медленные команды (SLOWLOG) или блокировка (WAIT, транзакции)
- Достижение лимита памяти (maxmemory) → eviction политика
- Фрагментация памяти
- Сетевые микролаги между контейнерами

### 4. **Временное решение при недоступности Redis**

> **Цель:** восстановить работу бота, даже если Redis недоступен.

**Решение:**  
**Переключиться в режим "только файловое хранилище" с отключением записи в Redis.**

#### Как:
1. В конфигурации `b24-support` временно отключить Redis:
   ```env
   REDIS_ENABLED=false
   SESSION_STORAGE=fallback_file_only
   ```
   или
   ```env
   DUAL_WRITE_MODE=primary_file
   ```

2. Перезапустить сервис:
   ```bash
   docker restart b24-support
   ```

3. Убедиться, что:
   - Файловое хранилище доступно.
   - Бот начинает отвечать.
   - Логи не содержат `File sync error`.

> **Альтернатива (если нельзя менять конфиг):**  
> Временно исправить права/место на диске и перезапустить reconciler вручную (если есть CLI-команда), чтобы восстановить синхронизацию.

### Резюме

- Основная подозреваемая причина — **сбой в файловом хранилище**, вызвавший `File sync error`, что привело к остановке reconciler и, как следствие, обработки сообщений.
- Диагностика начинается с проверки диска и прав.
- Временное решение — отключение Redis и переход на файловое хранилище как основное.
